# LLM-A*: Large Language Model Enhanced Incremental Heuristic Search on Path Planning

This repository provides an implementation and evaluation framework for a waypoint-guided path-planning approach, directly inspired by the methodology proposed in *"LLM-A*: Large Language Model Enhanced Incremental Heuristic Search on Path Planning"* (Meng et al., Findings of EMNLP 2024).

This project implements a 3D grid-based A* search that incorporates intermediate waypoints to guide the search. The primary goal of this repository is to evaluate how waypoint-guided search mechanisms perform under various configurations, particularly focusing on the algorithmic properties of the search independent of live LLM generation.

**Note:** This project is an independent implementation based on the concepts described in the paper. We do not claim to have invented the original algorithm.

## 1. Project Overview and Motivation

Standard A* guarantees finding an optimal path by using an admissible heuristic. However, in complex 3D environments with concave obstacles or local minima, geometric heuristics can draw the search into dense exploration, leading to a large number of expanded nodes.

The LLM-A* method proposes mitigating this by introducing high-level waypoints (potentially generated by an LLM) to guide the search. The algorithm sequentially targets these waypoints, aggressively pulling the search in a preferred direction to reduce node expansions.

This repository includes:
* **Standard A*:** A baseline admissible search.
* **Dijkstra:** A zero-heuristic optimal reference.
* **Waypoint-Guided LLM-A*:** A modified A* that incorporates intermediate targets into its priority function.
* **Evaluation Framework:** A comprehensive suite of experiments (E1–E8) using purely synthetic waypoints to isolate and rigorously evaluate the underlying pathfinding mechanism.

## 2. Technical Approach and Priority Variants

The core mechanism dynamically updates the target $t$. The priority function used to guide expansion is:

* **Baseline LLM-A*** (`PRIORITY_VARIANT = "baseline"`): $f(n) = g(n) + h(n, \text{goal}) + h(n, t)$. This applies an increased heuristic weight toward the intermediate target $t$. By double-counting heuristics, it overestimates costs and becomes **inadmissible**, sacrificing the global optimality guarantee in exchange for directed exploration.
* **Standard Goal Variant** (`PRIORITY_VARIANT = "standard_goal"`): $f(n) = g(n) + h(n, \text{goal})$. Used on the final leg to restore standard admissibility from the last waypoint to the goal. However, this does not establish global optimality for the entire route because prior legs were computed inadmissibly.

## 3. Architecture and Workflow

* `environment.py`: Defines the `Grid3D` representation, obstacle generation, and 26-connected movement rules (including unrestricted diagonal corner-cutting).
* `astar3d.py`: Core algorithms (Standard A*, LLM-A*, Dijkstra) and validation logic.
* `llm_planner.py`: HTTP client for querying a local Ollama API to generate waypoints. Includes validation and formatting logic.
* `config.py`: Global configuration for grid dimensions, variants, and API settings.
* `experiments/runner.py` & `main.py`: Entry points for executing automated experiments or single end-to-end runs.
* `visualization.py`: 3D path plotting using Matplotlib.

## 4. Experimental Evaluation Summary (E1–E8)

Our evaluation relies on **synthetic waypoints** (e.g., oracle, random, adversarial) generated algorithmically. This isolates pathfinding performance from live LLM inference delays or prompt hallucinations, evaluating how the search handles waypoints of varying quality. **These experiments do not establish the capability of a live LLM to generate such waypoints.**

Detailed results are available in the [Corrected Evaluation Report (FINAL)](experiments/CORRECTED_EVALUATION_REPORT_FINAL.md).

*   **E1 (Baseline Correctness):** Standard A* matched Dijkstra's optimal path in all 27 tested trials (0.00% cost gap), demonstrating the base engine correctly calculates geometric optimal distances in these scenarios.
*   **E2 (Waypoint Quality):** High-quality (oracle) waypoints drastically reduce node expansions (from a mean of 225 down to 19.5) but introduce a slight optimality gap (0.79%). Adversarial waypoints reduce expansions less predictably and exhibit extreme volatility (up to 1,626 expansions in one tested trial).
*   **E3 (Waypoint Count):** A single oracle waypoint significantly reduces expansions. Additional waypoints plateau the expansion benefits while increasing runtime overhead in our test setups.
*   **E4 (Ordering Sensitivity):** The algorithm is highly sensitive to waypoint sequence. Reversed or misordered waypoints resulted in substantial backtracking, increasing the mean node expansions from ~19 nodes up to over 1100 nodes in tested shuffle configurations.
*   **E5 (Priority Variants):** The `standard_goal` variant observed an optimality gap of 0.00% across the 20 tested configurations, but this does not constitute a theoretical global optimality guarantee. Additionally, this variant measured an increase in overall mean expansions to 227.4 nodes.
*   **E6 (Scalability):** LLM-A* expands a progressively smaller fraction of nodes compared to Standard A* as grid size increases (reaching 6% of Standard A* expansions at 40³ grids in our tests).
*   **E7 (Obstacle Density):** LLM-A* maintained a consistently lower expansion ratio (between 0.06x and 0.11x) across tested densities from 1% to 30%.
*   **E8 (Reprioritization Overhead):** Switching targets requires re-heapifying the OPEN set, introducing a measurable computational overhead (30% to 70% of total search time depending on grid size and waypoint count) that can potentially reduce the wall-clock time benefits of pruning nodes.

## 5. Limitations

1. **Optimality is Lost:** The baseline heuristic is inadmissible, meaning the method does not theoretically guarantee the shortest geometric path.
2. **LLM Inference Latency:** In our observed end-to-end trials with live local LLMs, API inference latency reached ~32 seconds, often bottlenecking the pipeline and eclipsing the sub-second execution time of Standard A*.
3. **Ordering Sensitivity:** The algorithm's expansion counts increase dramatically if waypoints are not provided in a geometrically logical sequence.
4. **Environment Simplification:** The current grid permits unrestricted diagonal corner-cutting through empty space. On physical robots with volume, this would cause collisions.
5. **Evaluation Scope:** The synthetic evaluation demonstrates how the algorithm behaves given specific inputs, but does not confirm that live LLMs can reliably generate valid, correctly ordered 3D waypoints.

## 6. Setup and Usage

### Prerequisites
* Python 3.10+
* [Ollama](https://ollama.ai/) running locally for LLM inference (if using `main.py` end-to-end).
* Required Python packages are listed in `requirements.txt`.

### Installation
```bash
git clone https://github.com/CrimsonKING3800/llm-path-planning.git
cd llm-path-planning/llm-astar
pip install -r requirements.txt
```

### Running Experiments
*   **End-to-End Pipeline:** Runs Standard A*, queries the LLM, runs LLM-A*, and dumps artifacts into `results/`.
    ```bash
    python main.py
    ```
*   **Automated Synthetic Benchmark:** Executes predefined failure cases against a Dijkstra baseline.
    ```bash
    python run_failure_cases.py
    ```
*   **Run Unit Tests:**
    ```bash
    python -m unittest discover tests
    ```
